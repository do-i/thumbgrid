## Replacement candidates: quality and speed

24 MP (6000×4000) source; quality on synthetic images, see the caveat below.

| Method | Viewer target 1920×1280, ms (4 threads / 1 thread) | Aliasing, zone plate (lower is better) | PSNR vs ideal Lanczos-3 (dB) | Dependency |
|---|---|---|---|---|
| OpenCV area (current, below 50%) | 16 / 56 | 14.0 | 49.2 | OpenCV |
| OpenCV area + unsharp (**current default look**) | 20 / 67 | 17.5 | 47.0 | OpenCV |
| **Qt smooth** | **5 / 5** | 14.0 | 48.9 | none (already used) |
| stb box | 39 / 39 | 14.0 | 49.2 | stb (single header) |
| stb Mitchell | 61 / 61 | **3.6** | 50.0 | stb |
| **stb Catmull-Rom** | 61 / 61 | 5.6 | **55.9** | stb |

PSNR rows are from the fractal image; the edge-and-text image ranks the methods the same way.

- **Qt smooth is effectively the same area filter as OpenCV** (same aliasing, within 0.4 dB) and about 3× faster. It can take over the big-downscale path with no new dependency.
- **Catmull-Rom is a real quality upgrade** (5–7 dB closer to ideal, about 3× less aliasing), but stb is single-threaded: about 60 ms per screen-sized frame versus OpenCV's 20 ms. This runs on the scaler worker, not the UI thread.
- **Duplicate hash:** a hand-written 32-point DCT matches `cv::dct` on 60/60 images. stb box + that DCT matches 58/60 (0.13 bits off on average). Qt smooth does not (9 bits off), so it can't be used for the hash.

## Risks

| # | Risk | Severity | Mitigation |
|---|---|---|---|
| R1 | **The default look changes.** Area+unsharp is deliberately crisp, while Catmull-Rom is cleaner (less moiré) and may read as slightly softer. | Medium | A/B the two on your own photos before switching. Keep an unsharp option (a small separable blur, about 40 lines) if crispness wins. |
| R2 | stb is single-threaded, so zooming very large images gets slower (about 3× for cubic-type scaling). | Low–medium | Use Qt smooth for downscaling (the fastest of all) and stb only for zoom-in and the 50–100% range. stb's split API allows threading later. |
| R3 | Saved settings hold CV filter values 2–4. The existing non-OpenCV fallback silently turns them into bilinear. | Medium | Explicit mapping plus a settings migration (there are already migration gates and tests for this). |
| R4 | 2/60 hashes differ slightly, so stored duplicate hashes go a little stale. | Low | Bump the hash-cache version: a one-time rehash. |
| R5 | stb maintenance. It moved to its own repo on 2026-10-19 (`nothings/stb_image_resize`, v2.50). Upstream fixes security bugs in public and slowly. | Low: it only sees decoded pixels, never file bytes | Vendor it pinned to a commit and treat updates like any third-party drop. |
| R6 | New in-house code (DCT about 25 lines, blur about 40) to maintain | Low | Unit tests compare against today's OpenCV outputs before OpenCV is removed. |
| R7 | stb picks its SIMD level at compile time (distro baseline x86-64), whereas OpenCV picks AVX2 at runtime | Low | Already reflected in the numbers above, which were built at baseline. |
| R8 | Quality numbers come from synthetic images (zone plate, fractal, test pattern) | — | The phase 2 A/B uses real photos. |

## Benefits summary

Removes 243 MiB and 20 packages from installs, 10 libraries and about 8 MB from every process, and about 8 ms from each launch. No more OpenCV CVE tracking, and the 2015 QtOpenCV glue goes away. Faster big-image downscaling (Qt), and an optional quality upgrade (Catmull-Rom). Smaller mac and Windows bundles and lighter CI images.
