# 2026-07-31-001 — XMP and ICC profile tabs in the File info panel

## Goal

Add XMP and ICC profile support to the File info panel as two new tabs sitting
next to EXIF. Their visibility follows the same rule shape EXIF uses, and a PNG
— which carries neither Exif that Exiv2 will write nor, today, any tab at all —
supports both XMP and ICC and therefore shows both tabs.

## Why this is cheap

No new dependency. Verified on this machine:

- `exiv2 0.28.8` is built with `EXV_HAVE_XMP_TOOLKIT` (`/usr/include/exiv2/exv_conf.h:58`),
  and `libexiv2.so` exports ~200 XMP symbols. `Exiv2::XmpData` is already read
  in `documentinfo.cpp:381` and copied in `imagestatic.cpp:141`.
- `Exiv2::Image` already exposes `iccProfile()`, `iccProfileDefined()`,
  `setIccProfile()`, `clearIccProfile()` (`image.hpp:188-221`).
- `QColorSpace::fromIccProfile()` / `description()` (Qt 6.11,
  `qcolorspace.h:118,151`) turns the raw blob into displayable fields, and
  `Qt6::Gui` is already linked transitively through `Qt6::Widgets`.

Empirical probe (throwaway, run 2026-07-31) confirmed the whole chain on a PNG:
Qt's PNG writer embeds a 480-byte ICC profile when the `QImage` carries a
colour space; `QColorSpace::fromIccProfile()` reads it back as `"sRGB"`; exiv2
writes `Xmp.dc.*` into that same PNG and the ICC chunk survives the write. This
is the recipe the test fixtures use — it is known-good, not a guess.

## Baseline

Commit `804e9f36` ("Hide the EXIF tab for formats Exiv2 cannot write Exif into")
is the starting point. It changed the EXIF tab from *disabled* to *hidden* and
narrowed the rule to "a format Exiv2 can write Exif into (jpeg/webp)". All 19
file-info/EXIF behaviour tests pass at that commit.

The rule to mirror, from `FileInfoDialog::populateExifTab()`:

1. the target is a file that exists, and
2. its `DocumentInfo::type()` is `STATIC` or `ANIMATED`, and
3. the *format* can carry this metadata kind — not whether this particular file
   happens to carry any today, and not whether the file is writable;
4. otherwise the tab is hidden (`setTabVisible(false)`), and if it was the
   current tab the dialog falls back to General;
5. when the tab is shown but the file carries nothing, a placeholder label says
   so rather than leaving a blank pane.

## Scope decision — read-only

XMP and ICC tabs are **read-only** in this change. The ask was "add support for
both" and "add tabs"; editing is a separate design (XMP would need its own
editable-key set with typed values — LangAlt, Seq, Bag — and "editing" an ICC
profile means replacing a binary blob, not typing into a field). The action
button row therefore stays exclusive to the EXIF tab, which is where the file is
written. Noted as a follow-up, not delivered here.

Consequence worth stating: because the tabs are read-only, their format
predicates gate on "can this format *carry* this metadata", which is broader
than EXIF's "can Exiv2 *write* Exif here". The rule *shape* is identical; the
predicate differs because the tab's purpose differs.

## Work items

### A — DocumentInfo backend (XMP + ICC)

Model: **Opus 5**. Rationale: exiv2 exception/lifetime handling, the
blob→`QColorSpace` conversion, lazy-load caching that has to match the existing
`exifLoaded`/`allTagsLoaded` pattern, and a latent thread-safety issue (below)
all need judgement rather than transcription.

- `static bool supportsXmp(const QString &filePath)` — jpg/jpeg/png/webp/tif/tiff.
- `static bool supportsIccProfile(const QString &filePath)` — same set.
  Keep both extension-based and next to `supportsMetadataEditing()`, matching
  its style and its `#ifdef USE_EXIV2` guard.
- `QMap<QString, QString> getXmpTags()` — lazy, cached in an `xmpTags` member
  with an `xmpLoaded` flag, keyed by exiv2 key (`Xmp.dc.title`), values the
  interpreted stream form, exactly as `loadAllTags()` does for its XMP section.
- `QMap<QString, QString> getIccProfileInfo()` — derived summary, not a raw
  dump. Rows: Profile (`description()`), Primaries, Transfer function, Profile
  size in bytes. Empty map when the file carries no profile.
- Every new exiv2 path wrapped in the same `try/catch(...)` +
  `qCWarning(logLoader)` shape the existing readers use.

### B — Latent XMP thread-safety fix

Model: **Sonnet 5**. Rationale: small, localized, one well-documented call pair.

`Exiv2::XmpParser::initialize()` is explicitly not thread-safe
(`xmp_exiv2.hpp:318`) and the toolkit currently self-initializes lazily on
whichever thread first reads XMP — already true today via `loadAllTags()`, and
this change adds more XMP readers. Call `initialize()` once on the main thread
at startup and `terminate()` at shutdown.

### C — FileInfoDialog tabs

Model: **Opus 5**. Rationale: three independently-hidden tabs interacting with
the existing current-tab fallback and the EXIF-only action button row is where
this change can actually break something that today works.

- `mXmpTab`, `mIccTab` built in the constructor immediately after `mExifTab`,
  same internal shape (rows container + rows layout + placeholder label), both
  starting hidden. Tab order: General, EXIF, XMP, ICC.
- `populateXmpTab()` / `populateIccTab()` mirroring `populateExifTab()`, called
  from the same place in `setTarget()`.
- `updateActionButtons()` must keep the button row on EXIF only — verify it
  keys on the EXIF tab specifically and does not leak buttons onto the new tabs.
- Test accessors mirroring `tabs()` so the behaviour tests can assert
  visibility.
- Update the class-header comment: it currently says "The two tabs differ in
  kind" and describes a two-tab dialog. That prose is now wrong.

### D — Behaviour tests

Model: **Sonnet 5**. Rationale: closely mirrors
`test_file_info_folder_and_exif_states.cpp`, and the fixture recipe is already
proven by the probe, so this is pattern-following with a known-good oracle.

New `src/tests/behavior/test_file_info_xmp_and_icc_tabs.cpp`, registered in
`src/tests/CMakeLists.txt` following the existing `thumbgrid_add_behavior_test`
blocks. Cases:

- PNG carrying XMP + ICC → XMP and ICC tabs visible, EXIF tab hidden.
- JPEG carrying all three → all three tabs visible.
- PNG with an ICC profile but no XMP → XMP tab visible with its placeholder.
- Folder / text file → all three tabs hidden, current tab falls back to General.
- Switching the target from a PNG to a folder while the ICC tab is current
  falls back to General rather than leaving a hidden tab selected.

Fixture recipe (proven): `QImage` + `setColorSpace(QColorSpace::SRgb)` + `save()`
for the ICC side; `Exiv2::ImageFactory::open()` → `xmpData()[...]` →
`writeMetadata()` for the XMP side.

Honour the `HOME` redirection convention from the existing behaviour tests —
the qttest home is shared across binaries.

### E — Doc comment pass

Model: **Haiku 4.5**. Rationale: mechanical prose cleanup, no design judgement.

Fold into whichever commit touches the file rather than as a separate pass.

## Sequencing — deliberately serial

The work items run **one subagent at a time**, not in parallel. They share one
`build/` directory, and concurrent builds there produce phantom failures where
one agent runs another's half-linked binary. A → B → C → D.

Commit after each item, single-line message, no trailers.

## Verification

`ctest --test-dir build` over the file-info/EXIF range plus the new test, run
with `QT_QPA_PLATFORM=offscreen QT_FORCE_STDERR_LOGGING=1`. The 19 tests green
at `804e9f36` must stay green — this change adds tabs, it does not alter EXIF
behaviour.

## Follow-ups, not in this change

- ICC profile replace/strip actions.
- `getAllTags()` already dumps XMP inline; once the XMP tab exists, showing the
  same properties in both places may be worth revisiting.
