# OpenCV removed (deltas to 2026-10-28-001)

## What your photos showed

62 HEIC photos at full screen on your 2192×990 display:

| Group | Legacy OpenCV path | Plain Qt | Fix without OpenCV |
|---|---|---|---|
| 41 shown at 50–100% | bicubic | about 20% softer, 5.7 dB further from an ideal resample | **own bicubic**: identical (max 1 level off, same 48.6 dB / 1.02 sharpness) |
| 21 shown below 50% | area + unsharp | softer | **Qt smooth + own unsharp**: identical (37.6 dB / 1.18 sharpness) |

You compared them visually (`~/img-photo-tst-compare/`) and chose the fixes. Since together they reproduce today's look exactly, **OpenCV was removed now instead of after the 2-release beta**. The scaling-engine toggle, its setting and the A/B action were dropped before ever being released.

**Correction to 001:** zooming past 100% never used the scaling engine. Qt's view draws it in both cases, so the "Zoom in" column there was wrong.

## Changes

| Area | Change |
|---|---|
| Viewer filters | **Nearest neighbor / Smooth / High quality** (default). High quality is bicubic, and below half size Qt smooth + unsharp. **"Sharpen images shrunk below 50%"** (default on) applies to High quality. |
| Stored values | 0, 1 unchanged; 2 (OpenCV "bilinear+sharpen", which never actually sharpened) → Smooth; 3, 4 → High quality. Resize dialog: 3 → High, 4 → High, sharpened. `scalingEngine` is pruned as a retired key. |
| Code | Removed `3rdparty/QtOpenCV`, `ImageLib::scaled_CV`, `USE_OPENCV`, and the engine toggle. Added `ImageLib::bicubicScaled` (Keys a = −0.75, OpenCV's kernel) and `scaledHighQuality`. One shared row-band threading helper. |
| Bug fixed on the way | `sharpen()` detached a shared image from several threads at once (a data race); it now detaches once before going parallel. |
| Build / packaging | `find_package(OpenCV)` removed. Dropped `opencv` from both PKGBUILDs, the Arch/test/mac workflows, the Windows build script and `scripts/dev.sh`. README, CONTRIBUTING and About updated. |
| Tests | `test_scaling_quality`: filter migration, sharpen invariants, bicubic reproduces a linear ramp, premultiplied alpha stays valid, each High-quality path, Settings round-trip, viewer requests. |

**Cost:** bicubic is 16–22 ms per full-screen frame vs OpenCV's 1–2 ms, on the background scaler thread (no UI blocking). It could later be sped up with fixed-point SIMD if it's ever noticeable.
